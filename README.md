# 地毯纹样修复台

给地毯修复车间角落（无网络、平板标注、两班次交接）使用的可续作修复台。

## 车间规则 → 系统行为

| 车间规则 | 实现 |
| --- | --- |
| 破损框按**图案坐标**记录 | 标记框存纹样归一化坐标 `[0,1]`，不绑定某张照片的像素 |
| 原图重新拍过后按**登记比例**迁移 | 重拍时做两点登记：旧图两个纹样特征点 ↔ 新照片对应点，自动算出比例 `s`；框由 `q = s·(p−锚点)` 正反映射 |
| 落在新图外的标记**单独列出** | 每个标记按新登记判定 `inside / partial / outside`，图外框从图上隐藏并在右侧单独分组（坐标保留，再取景包含时自动回来） |
| 补线颜色从**材料色卡**带出 | 标记指定材料，配色由色卡派生显示，不在档案里存死颜色 |
| 色卡批次一改，进行中配色**作废重算** | 色卡颜色/编号变化即批次 +1，服务端自动给所有进行中且用该材料的毯子追加 `reconcileBatches` 审计操作 |
| 已完工毯子**保留当时色卡** | 师傅完工确认时冻结 `completionSnapshot`（色号、颜色、批次号），之后换批不影响 |
| 工序：补线 → 编织 → 平整 → 完工 | 状态机推进；未登记领线时禁止进入编织 |
| 没领到线**退回上一步** | 撤销领线登记时，处于编织的工序自动退回补线 |
| 学徒只能加标记，完工要师傅确认 | 角色权限矩阵：学徒仅 `addMarker`；改档案/重拍/领线/推进/完工/发布色卡均需师傅 |
| 两人同时保存，后到不能盖先到 | 覆盖类操作（改档案、改标记、重拍）带 `baseRev` 乐观锁，过期返回 409；文本字段支持**按字段自动合并**，真冲突弹窗选边；坐标类冲突请技师在最新图上重做 |
| 离线标注回到网络后合并 | 本地 IndexedDB 存快照 + 操作队列 + 待传照片；在线逐条推送，离线归来走 `/api/sync`，按 opId 幂等去重，事实类操作（加标记/领线/推进…）双方都保留 |

## 运行

```bash
npm install
npm test           # 21 个测试：领域规则 14 + HTTP 接口 7（node --test，零依赖）
npm start          # 构建 + 单机服务（页面 + API + 照片），端口 62009
```

开发模式（前端热更新 + 独立 API）：

```bash
npm run dev:server # 同步服务器 :6210（JSON 存于 .data/）
npm run dev:web    # Vite :62009，/api 与 /photos 代理到 6210
```

首次启动写入 3 块演示毯：`CAR-092`（编织中）、`CAR-117`（补线中）、`CAR-138`（已完工，冻结旧批次靛蓝，换批后可对比）。

## 结构

```
shared/domain.js     领域核心（前后端共用纯函数）：登记/迁移、状态机、权限、
                     配色派生、色卡批次、字段级合并
server/              零依赖 Node HTTP 服务：写串行化 + 原子落盘 + 乐观锁 +
                     /api/sync 幂等合并 + 照片存储（JSON: .data/server-data.json）
src/store/store.tsx  离线优先状态层：本地先落地（规则离线同样生效）+ 队列 + 合并
src/lib/db.ts        IndexedDB（快照/队列/待传照片）、选图压缩
src/components/      标记图板（框选/锚点登记）、工序、标记配色、色卡、档案、同步坞
public/sw.js         外壳缓存（导航 network-first，照片 SWR），离线可打开应用
test/                domain.test.js（规则）+ api.test.js（真实 HTTP 端到端）
```

### 操作模型

- **事实操作**（`addMarker` / `setThreadIssued` / `advance` / `complete` …）追加保留，两班次各自的事实都会合入；
- **覆盖操作**（`updateRug` / `updateMarker` / `rephoto`）带版本号，冲突不静默覆盖；
- 每条操作有全局 `opId`，离线重连重复发送时服务端幂等跳过。
